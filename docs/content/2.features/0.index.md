# Controls

| Entity | Local only (RPC) | Hybrid Local + OCF |
| --- | --- | --- |
| Media player | Power, volume, mute, source, sound mode with RPC readback | Same RPC route |
| Select | Source: Input and Sound: Mode when locally supported | Same RPC route |
| Number | None | Tone: Woofer, Bass and Treble after independent validated OCF profiles |
| Switch | None | Sound: Night Mode, Bass Boost, Voice Amplifier, Virtual, Moderate Bass, SpaceFit Sound after validated OCF readback |
| Sensor | Local volume and source details when available | Same local values |

Woofer uses -12 to +6 dB, step 1. Bass/Treble use -6 to +6, step 1, without
an inferred dB unit. Profiles are model/firmware-scoped, not universal promises.
Late discovery uses the same entity IDs. Outages make discovered controls
unavailable; unknown readback is not a confirmed Off.

Commands check fresh local prerequisites, write once and require matching
readback. No audio action wakes the soundbar or switches transport after an
ambiguous write. Voice Amplifier is not Active Voice Amplifier.

No EQ select, seven-band EQ slider, playback play/pause/stop/next/previous,
speaker channel level, rear speaker mode or Active Voice Amplifier UI/action
is exposed. EQ backend metadata is diagnostic-only; useful app/DSP behavior
remains unconfirmed. Media metadata and artwork are unknown, not placeholders.

The retained integration actions are select_soundmode, set_woofer_level,
set_night_mode, set_bass_enhancer, set_voice_enhancer and set_space_fit_sound.
They target the media player and use the guarded local device methods.

Native translated Sound/Source/Tone prefixes group controls on HA's device page.
Custom entity names and existing IDs/history are preserved.

Read the [detailed readback and limitations guide](https://github.com/denyslietnikov/ha_samsung_soundbar#controls-and-readback).
